# Q2 Python 代码计划

## 目标与边界

- 实现目标：Python，下一正式轮次；生成唯一一套 Q2 面积方案并填写官方 `result2.xlsx` 副本。
- 批准决策：`q2_method_choice`、`q2_assumption_necessity` 与覆盖旧实现范围的 `q2_simplified_delivery_contract`。
- 主方法 `Q2-M1` 使用 20 个训练情景和半价销售规则；`Q2-B1` 是必须实现的中心路径 baseline，但不作为第二套正式交付方案。
- `Q2-F1` 保持休眠。只记录触发证据，不实现鲁棒模型，除非人工另行决定启用。
- 本契约不再要求两种销售规则分别优化、200/500 情景直接优化、五种子全面展开或管理参数网格搜索。

## 输入与共享约束

只读取 `workspace/data_clean/`，不得修改 `workspace/data_raw/`。复用 Q1 已验证的地块容量、适种性、连续种植季重茬、2023 至 2025 豆类窗口、后续滚动三年豆类覆盖和水浇地模式约束。正式配置固定为 `min_share=0.1`、`max_crops=3`；若修改，必须形成新的人类决策。

## 情景生成契约

2023 年为共同基期，年度变化逐年复利。所有概率分布仅是模拟假设：

- 小麦、玉米预期销量年增长率独立取 `[0.05, 0.10]`。
- 其他作物预期销量年变化率独立取 `[-0.05, 0.05]`。
- 亩产量年变化率独立取 `[-0.10, 0.10]`。
- 种植成本每年固定增长 5%。
- 粮食价格保持基准价，蔬菜价格每年固定增长 5%。
- 除羊肚菌外，食用菌价格每年的降幅独立取 `[0.01, 0.05]` 并按上一年价格复利；羊肚菌每年固定下降 5%。
- Q2 不引入作物间或经济变量间相关结构，该部分留给 Q3。

训练集使用 20 个有界均匀情景和固定种子 2026。测试集另用 200 个未参与优化的有界均匀情景和不同固定种子，并分别保存训练、测试样本哈希。端点压力至少包括全不利、全有利和一个逐因素不利组合；不再要求 100/200/500 情景规模网格。

## Q2-M1

1. 种植面积变量和出现指示变量不带情景索引，20 个训练情景共享唯一种植决策。
2. 每个训练情景使用自己的销量、亩产量、成本和价格，以及独立的正常销售辅助变量。
3. 只按半价销售规则 $\alpha=0.5$ 最大化 20 个情景的平均七年累计净收益。
4. 输出唯一的逐年、逐季、逐地块、逐作物面积方案；求解器目标必须与独立逐情景复算的平均收益一致。
5. 将该固定方案放入 200 个测试情景，分别按 $\alpha=0.5$ 和滞销压力规则 $\alpha=0$ 评估，不允许在测试情景中重新优化面积。

## Q2-B1

- 用变化区间中点构造逐年复利中心路径，固定趋势仍取题面约 5% 的中心值。
- 使用与主方法相同的硬约束、`min_share=0.1`、`max_crops=3` 和半价销售规则求解一套比较方案。
- 在与 Q2-M1 完全相同的 200 个测试情景和端点情景上，分别按半价与滞销规则事后评估。
- baseline 方案只保存为 CSV 和比较证据，不写入正式 `result2.xlsx`。

## 指标与比较

对主方案和 baseline，在同一测试情景下保存：

- 平均七年累计净收益；
- 5% 收益分位数；
- 最差 5% 情景平均收益，即收益方向的下尾 CVaR；
- 累计净收益低于 0 的情景比例；
- 最低情景收益和收益标准差；
- $H_1$、$H_3$、非零作物数和硬约束违规数；
- 求解时间、MIP Gap、模型规模和两方案面积重合度。

只有在主方案与 baseline 使用同一测试情景、同一销售规则且两者均无硬约束违规时，才允许写比较性优劣结论。亏损概率只解释为所设 200 个模拟情景中的频率，不外推为真实概率。

## 输出契约

目录为 `results/Q2/experiments/roundN/`：

- `tables/q2_m1_schedule.csv`：正式主方案；
- `tables/q2_b1_schedule.csv`：baseline 比较方案；
- `tables/result2.xlsx`：暂缓到最终交付阶段；届时从只读原模板复制并以 `q2_m1_schedule.csv` 为唯一填表来源，不改变格式；
- `tables/q2_paired_comparison.csv`：两种销售规则下的配对指标；
- `tables/q2_endpoint_stress.csv`：少量端点压力结果；
- `metrics/q2_metrics.json`：200 情景评价与集中度；
- `metrics/q2_solver_metrics.json`：主方法和 baseline 求解信息；
- `metrics/q2_scenario_config.json`：生成规则、种子和样本哈希；
- `figures/q2_expected_tail_comparison.*`：期望收益与下尾 CVaR 对比；
- `figures/q2_loss_risk_comparison.*`：亏损概率或收益分布对比；
- `run_summary.json`：批准决策、输入输出、运行状态、warnings、errors 和 fallback 证据。

Lean 阶段只要求上述机器证据和两张有明确主张的比较图，不生成常规长篇实验报告。

## Fallback 判定

若主方案在滞销或端点压力下出现亏损，或 200 个测试情景的最差 5% 平均收益相对平均收益下降超过 10%，或替代分布下方案重合度低于 70%，则在 `run_summary.json` 标记 Q2-F1 已观察到；不得自动实现或启用 fallback。

## 运行与复现

- 正式入口保持 `uv run python code/Q2/run_q2.py --round roundN --seed 2026 --time-limit 300`。
- 训练和测试情景必须隔离；固定随机种子并记录哈希。
- 异常、警告或复现需要时才创建 `logs/`。
