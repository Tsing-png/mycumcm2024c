# Q2 Python 代码计划

## 目标与边界

- 实现目标：通过“确定性求方案、随机情景做评估”的两阶段架构，生成唯一一套 2024 至 2030 年 Q2 正式种植面积方案。
- 当前批准决策：`q2_method_choice`、`q2_assumption_necessity` 与覆盖旧 SAA 契约的 `q2_decoupled_evaluation_contract`。
- Q2-M1 不再是全情景联合随机 MILP，正式名称为“期望趋势多期 MILP”。
- Q2-B1 为“2023 基期静态多期 MILP”，完成同一面积规划任务并提供可信 baseline。
- `code/Q2/q2_stochastic.py` 和既有 SAA 实验保留为规模失败证据，但正式入口不得调用该模型。
- Q2-F1 保持休眠，不自动实现或启用。

## 输入与共同约束

只读取 `workspace/data_clean/`，不得修改 `workspace/data_raw/`。Q2-M1 与 Q2-B1 必须复用相同的已验证约束：

- 地块容量、地块类型、季次和作物适种性；
- 连续种植季重茬约束，包括季间和跨年边界；
- 2023 至 2025 豆类窗口和后续滚动三年豆类面积覆盖；
- 水浇地水稻单季模式与两季蔬菜模式互斥；
- 两季蔬菜模式第二季只选 35 至 37 号作物中的一种并种满地块；
- 正式管理配置固定为 `min_share=0.1`、`max_crops=3`。

两种方法均按半价销售规则 $\alpha=0.5$ 求解。求解目标 Gap 为 1%，单次默认时限 300 秒；运行时间是观测指标，不承诺固定在 10 秒内。

## Q2-M1：期望趋势多期 MILP

使用 `center(data)` 构造 2024 至 2030 年期望趋势参数：

- 小麦和玉米销量每年增长 7.5%；
- 其他作物销量保持区间中点变化率 0%；
- 亩产量保持基准水平；
- 种植成本每年增长 5%；
- 粮食价格保持稳定；
- 蔬菜价格每年增长 5%；
- 除羊肚菌外的食用菌价格每年下降 3%，羊肚菌每年下降 5%。

上述趋势逐年复利。将这些单一路径参数传给 `solve_milp_schedule`，在 $\alpha=0.5$ 下求解唯一正式方案。保存求解时间、Gap、节点数、变量数、约束数和独立硬约束检查结果。

## Q2-B1：2023 基期静态多期 MILP

使用 `deterministic_maps(data)` 将 2023 年销量代理、亩产量、成本和价格保持到 2030 年不变。使用与 Q2-M1 完全相同的约束、管理配置和 $\alpha=0.5$ 销售规则，通过 `solve_milp_schedule` 求解 baseline。

Baseline 只用于样本外比较，不作为 `result2.xlsx` 的正式填表来源。

## 200 情景样本外评估

使用与优化阶段分离的 200 个有界均匀蒙特卡洛情景，固定测试种子并保存样本哈希。情景变化规则为：

- 小麦和玉米销量年增长率取 `[0.05, 0.10]`；
- 其他作物销量年变化率取 `[-0.05, 0.05]`；
- 亩产量年变化率取 `[-0.10, 0.10]`；
- 成本每年固定增长 5%；
- 粮食价格稳定，蔬菜价格每年增长 5%；
- 其他食用菌价格年降幅取 `[0.01, 0.05]` 并逐年复利，羊肚菌固定每年下降 5%。

Q2 不引入变量间相关结构，该部分留给 Q3。两套已求得的固定方案不得在测试情景中重新优化。

评估分别使用 $\alpha=0.5$ 和滞销压力规则 $\alpha=0$，计算：

- 平均七年累计净收益；
- 5% 收益分位数；
- 最差 5% 情景平均收益，即收益方向的下尾 CVaR；
- 亏损情景比例；
- 最低收益和收益标准差；
- $H_1$、$H_3$、非零作物数和硬约束违规数；
- 两套方案的面积重合度。

评估优先采用向量化计算。必须随机抽取若干情景，与 `evaluate_schedule` 的逐情景精确分段销售计算核对；误差超过数值容差则评估失败。亏损概率只解释为这 200 个模拟情景中的频率。

## 最小输出契约

目录为 `results/Q2/experiments/roundN/`：

- `tables/q2_m1_schedule.csv`：唯一正式方案及最后填表来源；
- `tables/q2_b1_schedule.csv`：baseline 比较方案；
- `tables/q2_paired_comparison.csv`：两种销售规则下的主方案与 baseline 指标；
- `metrics/q2_metrics.json`：配对评估、面积重合度、集中度和向量化核对结果；
- `metrics/q2_solver_metrics.json`：两种确定性 MILP 的求解信息；
- `run_summary.json`：批准决策、方法状态、输入输出、核心指标、warnings、errors 和 fallback 状态。

当前阶段不生成 Excel、端点压力表、常规实验报告或论文图。`result2.xlsx` 在最终交付阶段从只读原模板复制，并仅使用 `q2_m1_schedule.csv` 填写。

## 成功与 fallback 判定

Q2-M1 和 Q2-B1 只有同时满足以下条件才标记为成功：

- 方案非空；
- 独立硬约束违规数为 0；
- 求解器正常结束且实际 MIP Gap 不超过 1%，或达到时限但实际 Gap 仍不超过 1%；
- 样本外评估与逐情景核对通过。

若主方案无可行解、Gap 超过 1%、样本外出现亏损、下尾 CVaR 相对平均收益下降超过 10%，或评估核对失败，则在 `run_summary.json` 标记 Q2-F1 已观察到，但不得自动启用 fallback。

## 运行与复现

- 正式入口：`uv run python code/Q2/run_q2.py --round roundN --seed 2026 --time-limit 300`。
- 固定随机种子，保存测试情景哈希和 Python、NumPy、Pandas、SciPy 版本。
- 只在失败、警告或复现异常时创建日志。
