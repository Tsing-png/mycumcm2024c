# Q2 Python 代码计划

## 目标与边界

- 实现目标：Python，`round1`。
- 批准决策：`q2_method_choice` 与 `q2_implementation_contract`。
- 主方法 `Q2-M1`，baseline `Q2-B1`；两者完整实现并共享约束、管理网格、销售规则、测试情景和指标。
- `Q2-F1` 不实现。若替代分布或端点下 5% 下尾平均收益相对主设定变化超过 10%，或方案重合度低于 70%，仅记录触发并返回人工决策。

## 输入与共享约束

输入字段、单位、合法槽位、连续季重茬、三年豆类面积覆盖、管理阈值网格和模板约束完全复用 Q1 计划。Q2 还必须读取题面中各作物类别的年度变化规则，并在配置中保存为机器可读参数，不从论文补充概率或数值。

## 情景生成契约

所有年度变化逐年复利，2023 为共同基期。主情景采用有界均匀抽样：

- 小麦、玉米预期销量年增长率独立取 `[0.05, 0.10]`。
- 其他作物预期销量年变化率独立取 `[-0.05, 0.05]`。
- 亩产量年变化率独立取 `[-0.10, 0.10]`。
- 种植成本每年固定增长 5%。
- 粮食销售价格保持基准价；蔬菜价格每年固定增长 5%。
- 除羊肚菌外食用菌价格年降幅独立取 `[0.01, 0.05]`；羊肚菌固定年降 5%。
- Q2 中不同作物、变量和年份的随机抽样相互独立；这是比较设定而非观测事实。

主优化规模先用 200 个情景，固定种子组 `[2024, 2025, 2026, 2027, 2028]`。规模检查使用 100/200/500 情景。替代形状使用同范围、众数为区间中点的三角分布；端点压力测试至少包含全不利、全有利和逐因素不利情景。所有情景保存配置、种子、样本哈希和摘要，不必保存冗余控制台日志。

## Q2-M1

1. 种植面积与出现指示不带情景索引，是情景实现前的共享决策。
2. 每个情景按实现的销量、亩产量、成本和价格建立产销及收益辅助量。
3. 对 $\alpha=0$ 和 $\alpha=0.5$ 分别最大化 200 个主情景的平均七年累计净收益。
4. 5% 分位收益、最差 5% 平均收益和亏损情景比例只作为输出指标，不进入目标或硬约束。
5. 在未参与优化的配对测试情景、替代分布、端点情景和其余固定种子上评估方案。

## Q2-B1

- 用各区间变化率中点构造逐年复利中心路径；固定约 5% 的趋势仍取 5%。
- 在相同七年 MILP 约束和管理候选下最大化中心路径净收益。
- 将所得单一计划放到与 Q2-M1 完全相同的测试情景及两种销售规则中事后评估。

## 输出契约

目录为 `results/Q2/experiments/round1/`：

- `tables/q2_m1_*_schedule.csv`、`q2_b1_*_schedule.csv`，保持年、季、地块、作物、面积粒度。
- `tables/q2_management_grid.csv`、`q2_scenario_summary.csv`、`q2_paired_comparison.csv`、`q2_endpoint_stress.csv`。
- `metrics/q2_metrics.json`、`q2_seed_stability.json`、`q2_distribution_sensitivity.json`、`q2_solver_metrics.json`。
- `figures/` 可保存收益分布、主方法与 baseline 配对差和收益-集中度比较图。
- `run_summary.json` 记录种子组、方法、销售规则、输入输出、运行时间、warnings、errors 和 fallback 状态。
- `tables/result2_*.xlsx` 保存官方模板副本；原始模板只读。

共同指标为测试情景平均累计净收益、5% 分位收益、5% 下尾平均收益、亏损比例、$H_1$、$H_3$、非零作物数、管理复杂度、`N_viol`、方案重合度、运行时间和 gap。没有 baseline 与配对证据时不得产生“更优”标志。

## 运行与复现

- 入口：`uv run code/Q2/run_q2.py --round round1 --seed 2026`；内部展开批准的五种子组。
- 优化与测试情景必须分开，并记录样本哈希。
- 预计先完成 100/200 场景，500 情景只作规模验证；单次 15 分钟限时，异常时才写 `logs/`。
